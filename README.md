# AutoTouchpadBlocker (InputGuard)

외장 마우스가 연결되어 있는 동안 노트북 내장 터치패드를 자동으로 끄고, 외장 마우스가 사라지면 다시 켜 주는 Windows 트레이 프로그램입니다. 터치패드에 손이 스쳐 커서가 튀거나 클릭되는 사고를 막는 용도입니다.

- 대상: Windows 10/11, 개인 PC 1대용
- 구현: C# / .NET 10 / WinForms, 외부 패키지 없음
- 실행 파일 이름은 `InputGuard.exe` 입니다.

## 동작 방식

1. **장치 감지** — Raw Input API로 키보드/마우스 장치의 연결·해제를 실시간으로 받습니다.
2. **외장/내장 판정** — 장치 인스턴스 ID의 부모 체인을 따라가 버스를 봅니다.
   - Bluetooth(클래식/BLE), USB(유선·2.4GHz 수신기) → 외장
   - 체인에 ACPI가 있고 USB/Bluetooth가 없음(PS/2, I2C) → 내장
   - 그 외(ROOT, SWD, 원격 데스크톱 등) → 가상, 무시
3. **물리 장치 묶기** — 한 장치가 노출하는 여러 HID 컬렉션(예: 마우스가 가진 키보드 컬렉션)을 USB 복합 장치 노드 또는 Bluetooth 주소 기준으로 하나로 묶습니다.
4. **역할 학습** — 외장 장치는 실제 입력이 들어와야 역할을 인정합니다. 마우스 이벤트 40회 이상이면 마우스, 키 이벤트 6회 이상이면 키보드. 학습 결과는 설정 파일에 저장되어 다음 연결부터 바로 적용됩니다. (마우스가 키보드 컬렉션을 노출해서 생기는 오탐 방지)
5. **터치패드 끄기/켜기** — 외장 마우스가 있으면 터치패드 장치를 장치 관리자의 "사용 안 함"과 같은 방식(`CM_Disable_DevNode`)으로 끕니다. 정밀 터치패드는 마우스 컬렉션과 터치 패드 컬렉션이 따로 있으므로 HID 컬렉션이 아닌 그 부모 장치(I2C HID 장치 전체)를 끕니다. 외장 마우스가 사라지면 약 1초 안에 다시 켭니다.
6. **알림** — 상태가 바뀔 때마다 트레이 풍선 알림을 띄웁니다.

## 안전장치

- 앱 종료, 로그오프/시스템 종료, 처리되지 않은 예외 시 꺼 둔 장치를 모두 다시 켭니다.
- 꺼 둔 장치 목록을 설정 파일에 기억해 두고, 비정상 종료 후 다시 시작하면 먼저 복구한 뒤 상태를 재적용합니다.
- 프로세스가 강제 종료(작업 관리자 등)되면 위 정리 코드가 실행되지 못하고, 꺼진 상태는 재부팅 후에도 남을 수 있습니다. 이때는 InputGuard 를 다시 실행하면 시작 시 복구가 터치패드를 켭니다.
- 자동 시작 작업은 배터리 전환·실행 시간 제한으로 강제 종료되지 않도록 등록하고, 비정상 종료 시 1분 뒤 다시 시작합니다. 예전 방식으로 등록된 작업은 실행 시 자동으로 새 정의로 바꿉니다.
- 트레이 메뉴 "일시 중지"를 누르면 즉시 터치패드가 켜집니다.

## 요구 사항

- .NET 10 SDK (빌드용). 실행에는 .NET Desktop Runtime 10 이 필요합니다.
- 장치 비활성화에 관리자 권한이 필요합니다. 매니페스트에 `requireAdministrator` 가 들어 있어 실행 시 UAC 창이 뜹니다. 로그인 시 자동 시작을 등록하면 UAC 없이 시작됩니다.

## 빌드와 실행

```bash
dotnet build InputGuard -c Release
```

실행 파일: `InputGuard\bin\Release\net10.0-windows\InputGuard.exe`

명령줄 인수:

| 인수 | 설명 |
|---|---|
| `--autostart on` | 로그인 시 자동 시작 작업(작업 스케줄러 `InputGuard`, 최고 권한)을 현재 실행 파일 경로로 등록하고 계속 실행 |
| `--autostart off` | 자동 시작 작업 해제 |
| `--exit` | `--autostart` 처리만 하고 종료 |

폴더를 옮기면 자동 시작 작업이 옛 경로를 가리키므로 `InputGuard.exe --autostart on` 으로 다시 등록해야 합니다.

## 트레이 메뉴

- **장치 목록 / 상태 보기** — 연결된 장치, 외장/내장 분류, 학습된 역할, 입력 활동 횟수, 현재 꺼둔 장치
- **지금 다시 검사** — 장치 재열거
- **일시 중지 (터치패드 켬)** — 토글
- **로그인 시 자동 시작 (관리자)** — 작업 스케줄러 등록/해제
- **설정 파일 열기 / 설정 다시 읽기 / 학습된 역할 초기화 / 로그 열기**
- **종료 (터치패드 켬)**

## 설정과 로그

위치: `%LOCALAPPDATA%\InputGuard\`

- `InputGuard.settings.json`
  - `MouseEventThreshold`, `KeyboardEventThreshold` — 역할 학습 임계치
  - `MinInternalKeyboardKeys` — 키 수가 이보다 적은 내장 키보드(핫키 전용)는 기본 제외
  - `GuardKeyboard` — `true` 면 외장 키보드가 있을 때 내장 키보드도 끔. 기본 `false`. 많은 노트북의 내장 키보드(PS/2, I2C)는 Windows 가 비활성화를 거부하므로 동작하지 않을 수 있음
  - `Devices` — 장치별 역할. 외장 장치는 `Keyboard`/`Mouse` 를 손으로 고치고 `Manual: true` 로 두면 학습이 덮어쓰지 않음. 내장 장치는 `Exclude: true` 로 두면 비활성화 대상에서 제외
  - `DisabledDevices` — 현재 꺼 둔 장치(복구용, 직접 편집하지 않음)
- `InputGuard.log` — 장치 연결/해제, 역할 학습, 끄기/켜기, 오류

## 알려진 제한

- 내장 키보드는 다루지 않습니다. 이 PC의 내장 키보드 두 개(PS/2, I2C)는 Windows 가 비활성화를 거부했고, 장치 제거 방식도 드라이버가 거부하거나 재부팅 전까지 적용되지 않아 실시간 토글이 불가능했습니다.
- Bluetooth 마우스가 절전에 들어가 장치가 사라지면 터치패드가 잠시 켜졌다가, 마우스가 깨어나면 다시 꺼집니다.
- 새 외장 마우스는 처음 연결했을 때 약간 움직여야(이벤트 40회) 마우스로 인정됩니다. 그 전까지는 "미정(입력 대기)" 로 표시됩니다.

## 소스 구성

| 파일 | 역할 |
|---|---|
| `Program.cs` | 진입점, 명령줄 인수, 중복 실행 방지 |
| `TrayAppContext.cs` | 트레이 아이콘·메뉴, Raw Input 감시 창, 상태 변화 알림, 안전장치 훅 |
| `InputDevice.cs` | Raw Input 장치 열거, 인스턴스 ID 변환, 외장/내장 분류, 물리 장치 키 |
| `GuardEngine.cs` | 설정 파일, 물리 장치 묶기, 입력 활동 집계, 역할 학습, 상태 계산 |
| `DeviceGuard.cs` | 장치 노드 끄기/켜기, 꺼 둔 장치 기억과 복구 |
| `Autostart.cs` | 작업 스케줄러 등록/해제 |
| `NativeMethods.cs` | user32 / cfgmgr32 P/Invoke |
| `app.manifest` | 관리자 권한 요청 |
